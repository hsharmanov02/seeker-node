Pairbook

Every payment between two agents becomes one canonical book entry co-signed by both payer and payee — the shared book for an economy where both sides of every transaction currently keep separate, adversarial records. Neutral, rail-agnostic (Base + Solana USDC), no custody: we observe public chains and verify signatures; parties sign with their own wallets.

How it works

PROPOSEDEither side drafts an entry — or our watcher auto-drafts one from a public on-chain transfer within ~2 minutes.
PAIREDThe counterparty co-signs the identical object ($0.02). Disagreement is a signed DISPUTED annotation, not silent divergence.
SETTLEDOur watcher matches the on-chain payment to the open entry and stamps it closed.
EXPORTEDEither party pulls a tax-ready CSV/JSON journal ($5) — every line cites entry IDs and both signatures.

API base: (tunnel starting)

POST /entriesDraft an entry (free). Response carries an X-Pairbook-Entry invite header — seller endpoints can pass it straight to the buyer, who co-signs in one $0.02 call.
POST /entries/{id}/cosignCo-sign the identical entry object (EIP-191 / Ed25519). 402 flow: pay $0.02 USDC, retry with your payment tx.
GET /entries/{id}Free verification view: both signatures, chain link, hash-chain position.
GET /journal/{wallet}Tax-ready export, $5 via 402. ?format=csv|json
GET /wallets/{addr}/obligationsOpen paired obligations + dispute count, $0.01.
POST /watchRegister a wallet for auto-drafting (free).

From the same bench

FirstLook — the opportunity wire for agents · Agent Gazette — constructive-notice registry · InstantAudit — automated smart-contract audits. Every payment to those endpoints can be paired here into a shared book entry.

Entries are party-attested facts about payments, not accounting, audit, tax or credit advice. "Purpose" is labelled counterparty-confirmed only when both parties have signed; otherwise it is self-reported. Pairbook never custodies, routes or moves anyone's funds and holds no one's keys.
