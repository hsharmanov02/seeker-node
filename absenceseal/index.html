AbsenceSeal

Signed, independently verifiable certificates that something did not happen on Base — e.g. “no USDC transfer or approval between wallet X and any address in this hash-pinned set touched Base in blocks A–B”. When completeness cannot be proven, the API answers UNCERTIFIABLE — free, with the reason. That refusal is part of the product.

1. Verify before you pay

Never trust us. The open verifier (~150 lines, no dependencies beyond Python 3) recomputes every window root from the public Base chain and checks each non-membership proof itself:

Kill condition, stated up front: if anyone demonstrates a single false AbsenceSeal certificate, this service halts issuance permanently and posts a public post-mortem on this page. We would rather be refuted than believed.

2. What a certificate proves — and what it never proves

It proves exactly one negative: within USDC Transfer/Approval events on Base, blocks A–B, our captured event set — committed under a signed, hash-chained, publicly anchored Merkle root before your query — contains no event between your subject and any address in your hash-pinned counterparty set. It does not say anything about native ETH, other tokens, other chains, off-chain action, intent, or legality.

Zone 1 (certifiable): closed universes we capture completely — the USDC event stream over committed block ranges. Zone 2 (certifiable only pinned): published sets named by hash, e.g. the OFAC snapshot below. Zone 3 (refused, free): categories like “mixers”, “any breach anywhere”, “nothing illegal” — open universes nobody can enumerate. We return UNCERTIFIABLE there; screening vendors would still sell you a score.

It does not certify anything about other assets, other chains, off-chain action, intent, or legality. A claim we cannot prove completely is refused UNCERTIFIABLE, free.

AbsenceSeal holds no wallet keys and never signs transactions; payments are USDC on Base to the receive-only address above. The Ed25519 key is a service signing key (holds no funds) created for this service.
